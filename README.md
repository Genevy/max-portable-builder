# MAX Portable — портативный клиент MAX для Windows

📦 Репозиторий на GitHub: <https://github.com/Genevy/max-portable-builder>

![MAX Portable](preview.webp)

Портативный клиент мессенджера **MAX** для Windows 10/11 x64 — нативная оболочка
над официальной веб-версией <https://web.max.ru/>, построенная на
[Tauri v2](https://v2.tauri.app/) и WebView2 с использованием
[Pake](https://github.com/tw93/Pake). Без Electron.

> Официального портативного клиента MAX для Windows на момент
> создания проекта не существовало (доступны только веб-версия, десктопные и мобильные
> приложения). MAX Portable закрывает эту нишу для личного использования:
> отдельное окно, портативный профиль, нативные диалоги сохранения файлов.


## Правовая оговорка

Настоящий проект является **неофициальной фан-сборкой**, созданной для личного
использования, так как официальной портативной версии на сегодняшний день нет.
Он **не связан** с ООО «MAX», не является официальным клиентом MAX и не
распространяется как коммерческий или публичный продукт.

Все права на сервис MAX, его наименование, товарные знаки, логотипы и содержимое
принадлежат их правообладателям — **ООО «MAX»** (<https://legal.max.ru/ps>). 
Приложение не изменяет, не модифицирует и не обходит сервис MAX: 
оно лишь отображает официальную веб-версию в изолированном окне
WebView2 средствами Pake.

Используя настоящую сборку, вы подтверждаете, что делаете это на свой риск и в
рамках условий использования сервиса MAX.


## Назначение и архитектура

MAX Portable решает задачу удобного доступа к веб-версии MAX в виде отдельного
настольного приложения — без браузерной вкладки, с портативным профилем и
нативными диалогами сохранения файлов.

Архитектурно приложение представляет собой оболочку Tauri:

- **Frontend** — официальная веб-версия MAX, загружаемая в WebView2;
- **Backend** — Rust-код Tauri, обеспечивающий окно, навигацию, загрузку файлов,
  системные диалоги и уведомления;
- **Инъекции** — только штатные скрипты Pake (`src-tauri/src/inject/*.js`);
  сторонние инъекции в DOM сайта MAX не выполняются.

Такой подход даёт малый размер дистрибутива (≈8 МБ), быстрый запуск и умеренное
потребление памяти по сравнению с решениями на Electron.

## Возможности

### Портативность
Профиль WebView2 (`data/`) размещается рядом с исполняемым файлом. Вход в аккаунт,
кэш и сессия сохраняются между запусками и переносятся вместе с каталогом
приложения.

### Управление учётными данными
Пароль не сохраняется (`password_autosave: false`). В профиле хранится только
сессионный токен — аналогично поведению обычного браузера. При выходе из аккаунта
и повторном запуске требуется авторизация по QR-коду или номеру телефона.

### Загрузка файлов
Скачивание выполняется через системный диалог «Сохранить как»:

- **Медиа (фото, видео)** — имя формируется по локальному времени:
  `2026-11-01_HH-MM-SS.png` / `.mp4`;
- **Документы, архивы и прочие файлы** — сохраняются с исходным именем и
  расширением (`file.docx`, `report.pdf`, `archive.zip`).

Поддерживаются оба пути загрузки MAX: blob-URL (фото) и прямые HTTP-ссылки
(видео), с корректным определением расширения по `Content-Type`.

### Уведомления
Нативные тосты информируют об ошибках сохранения и сбоях HTTP. Язык тостов
выбирается по системной локали (английский/китайский).

### Прочее
- Ярлык на рабочем столе.
- DevTools в релизной сборке не открываются.
- Ограничение кэша: 50 МБ диск + 25 МБ медиа.
- Поддержка только x64; требуется WebView2 Runtime.

## Требования

- Windows 10/11 **x64** (x86 не поддерживается).
- **WebView2 Runtime** — на Windows 11 из коробки; на Windows 10 может потребоваться
  установка: <https://developer.microsoft.com/microsoft-edge/webview2/>.
- **Node.js** >= 22 (LTS); минимум 20.9 (по `engines` в `package.json`).
- **pnpm** — версия из `packageManager`: `pnpm@10.26.2`.
- **Rust** >= 1.85 (MSVC toolchain): <https://rustup.rs/>.
- **Visual Studio Build Tools 2022 или новее** (x64, workload
  «Desktop development with C++») — для `tauri build`.
  Скачать: <https://visualstudio.microsoft.com/ru/downloads/>
  (раздел «Build Tools для Visual Studio»; подойдёт и полная Visual Studio
  с workload «Desktop development with C++»).
  Без MSVC-тулчейна (`cl.exe`, `link.exe`, Windows SDK) сборка падает
  с «link.exe not found».


## Сборка

```cmd
git clone https://github.com/Genevy/max-portable-builder.git
cd max-portable-builder
pnpm install
pnpm run build
```

> При `pnpm install` возможно предупреждение `WARN ... ERR_PNPM_EPERM.
> Will retry ...` — это разовая блокировка файла антивирусом; pnpm повторяет
> попытку и завершает установку. Предупреждение безопасно.

### Пересборка

Когда проект уже склонирован и зависимости установлены. Перед сборкой закройте
запущенный клиент: `scripts/copy-portable.js` перезаписывает exe, и Windows
возвращает `EPERM`.

```cmd
taskkill /IM MaxPortable.exe /F
pnpm run build
```

### Результат

Пути — от корня репо (проекта):

- `pnpm install` → `schema/` (JSON-схема Pake);
- `pnpm run build` → `build/max-portable/MaxPortable.exe` (готовый клиент);
- первый запуск → `build/max-portable/data/` (профиль: вход, кэш).

Профиль `data/` при пересборке не удаляется (`copy-portable.js` его сохраняет),
поэтому вход в аккаунт не теряется.

> Если `pnpm run build` завершается ошибкой линкера (`link.exe not found`),
> запустите сборку из **Developer Command Prompt for VS** (x64): там
> `vcvarsall.bat x64` настраивает PATH/INCLUDE/LIB для MSVC.

## Запуск

```cmd
cd build\max-portable
start "" MaxPortable.exe
```

Профиль (вход, кэш) создаётся в `build\max-portable\data\` при первом запуске.
На рабочем столе создаётся ярлык для запуска.

## Технические заметки

- Каталог `data/` рядом с exe **не изменять вручную** — в нём вход и кэш.
- Служебный каталог pnpm не настраивается: используется стор по умолчанию
  (`%LOCALAPPDATA%\pnpm\store`), привязки к конкретному диску нет.
- Отладочный лог не пишется: запуск без перенаправления вывода в файл.
- PowerShell может блокировать pnpm (ExecutionPolicy) — используйте `cmd`.

## Ограничения

- Только Windows x64; x86 и другие ОС не поддерживаются.
- Приложение не является официальным клиентом MAX и не гарантирует
  совместимость при изменениях веб-версии.
- Пароль не сохраняется; сессия хранится в портативном профиле.
- Готовые бинарники в репозитории не публикуются (см. «Распространение»).

## Распространение

Репозиторий содержит **только исходный код**. Готовые `exe`/`msi` в Releases
**не публикуются**: это соответствует условиям использования сервиса MAX и
позволяет избежать распространения клиента от чужого имени. Сборка выполняется
локально по инструкции выше.
